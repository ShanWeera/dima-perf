title: Design rationale

---

The methodology pages justify every scientific choice with peer-reviewed sources. This page
gives the reasons for the engineering and user-experience choices. These need no peer-reviewed
source (the project's working agreement 9); where one is cited, it follows the project's
citation policy: peer-reviewed domain work (bioinformatics, computational biology, virology,
microbiology, ecology and evolution, biostatistics) first; general human–computer interaction,
visualisation, statistics, mathematics (including numerical analysis) or computer-science
sources only where they are the primary source of a number, algorithm, theorem, finding or
experiment, marked **[general]**; standards and specifications, cited for what they define,
marked **[standard]**. Some rows say where no peer-reviewed source exists (**gap**) and name the
evidence used instead.

## Command line

| Choice | Rationale and sources |
|---|---|
| Option names follow the paper's terms (`--support-threshold`, `--kmer-length`, `--alphabet`), every option has a documented default, and `-h` gives a summary while `--help` explains each option with its references | A tool prints help when run without parameters and has `-h` and `--help` switches [@seemann2013, Recommendations 1 and 2]; it exposes a small set of parameters by default, with conservative defaults, and describes the others in its documentation [@list2017, Rule 5]. |
| All options and outputs are checked before the input is read; conflicting or ambiguous outputs are refused (for example `-O` against the file extension) | Users make mistakes, so a tool should check its input and explain what is wrong [@list2017, Rule 6] and validate its parameters before its main work starts [@seemann2013, Recommendation 6]; checked first, a mistake costs seconds, not an hour of computation. |
| Errors name the file, record, line, column and byte, and end with a `hint:` | Error messages should provide solutions or point to more information [@lee2018, Rule 9]. |
| Recoverable conditions are reported once per kind, with a count, examples and a hint, in the results (`run.diagnostics`) and on standard error | Logs help users pinpoint problems and make their research reproducible [@list2017, Rule 7]; reporting each kind once, with a count, keeps them short enough to read. Recording them with the results keeps the provenance complete [@wilkinson2016] [general]. |
| Quiet by default (warnings, errors, one summary line); `-q` errors only; `-v` progress milestones and a performance report | Progress messages help users pinpoint errors [@list2017, Rule 7]; behind `-v` they leave a normal run's output short. |
| Colour only reinforces text (`error:`, `warning[code]:`); `NO_COLOR` and `--color` are honoured | Colour must not be the only visual means of conveying information [@wcag22, SC 1.4.1] [standard]. |
| Progress is one plain ASCII line on a terminal (`counting k-mers: 62%, 1652 sequences, 5.6 MB of 9.1 MB`), redrawn in place only when its whole percentage changes or a second passes; `--progress plain` (or `DIMA_PROGRESS=plain`) appends a line per phase and the progress at most every 10 seconds and at least once a minute, for screen readers and logs (and in logs at `-v`); `--progress off` shows nothing | Progress display is a valued usability feature of sequence tools [@shen2024]; progress belongs on standard error [@seemann2013]; users rely on progress indicators to see that an operation is proceeding [@harrison2007] [general]. Screen readers read the characters of graphical bars aloud and every redraw, and every command should still report its status and progress [@sampath2021, §5.3.2 and Recommendations 5 and 6] [general], hence the appended `plain` lines (as Snakemake and minimap2 print by default; tool behaviour, no peer-reviewed source); measured with NVDA's own diffing and eSpeak, a text line redrawn per percent queues about a sixth of the speech of a 10 Hz bar. Content that updates by itself needs a way to stop it [@wcag2ict, SC 2.2.2] [standard]. No escape sequences and no box-drawing glyphs: they break under `TERM=dumb`, the C locale and Windows consoles. |
| The end-of-run line gives the results and the time (`analysed 191 sequences, 1345 positions (1345 eligible) in 0.21 s; entropy mean 0.1261, min 0.0000, max 1.5878 bits`), with `--similarity-weighted-entropy` its mean next to the observed entropy of the same positions (`; similarity-weighted mean 0.0363 bits (observed 0.1207)`: like for like, since the corrected mean is not comparable), adds `N warnings (see above)` only when there are warnings, and is the last line; a value that is not zero never reads `0.0000` (`< 0.0001`) | The paper reports exactly these quantities [@tharanga2025, Results]; a program should tell users what it actually did [@taschuk2017, Rule 10]. A count that is shown even at zero becomes a habituated token that is ignored when it changes [@ancker2017] [general]; [@vandersijs2006] [general]. |
| Numbers in messages are plain digits (`2637`, not `2,637`); durations and sizes use unit symbols (`s`, `min`, `h`, `kB`, `MB`), rounded before the unit is chosen | Digit grouping with commas is ambiguous across locales: the SI allows the comma as the decimal marker, never puts commas or dots between groups of digits, and makes grouping a matter of choice that is not always followed in scripts read by a computer [@bipm2019, §5.4.4] [standard]; speech synthesisers misread `2,637` in most voices (measured with eSpeak NG). A unit symbol follows the number after a space [@bipm2019, §5.4.3] [standard]; `min` and `h` are units accepted for use with the SI [@bipm2019, Table 8] [standard]. |
| Messages are ASCII: `at least`, `X to Y`, `...`, `U+200B (3 times)`; `--help` uses ASCII words and ASCII formulas (`100*T/N`, `(D - 1)/(2N ln 2)`); only authors' names keep their letters | Screen readers do not read non-ASCII symbols as intended [@sampath2021, Recommendation 6] [general]; measured: `man` in the C locale drops the ceiling brackets, `less` and PowerShell show byte sequences, and screen readers are silent on them. The methodology pages keep typeset formulas. |
| Percentages are written `62%`, without a space, in messages, help, documentation and the desktop app | The paper writes every percentage this way [@tharanga2025], as do nearly all recent papers in the field's journals (213 of 214 measured); a spaced `%` can wrap onto its own line in `--help`. This deviates from the SI, which separates the number and `%` by a space [@bipm2019, §5.4.7] [standard]. |
| Distinct exit codes per class of failure (usage, I/O, invalid data), and 128 + signal number after an interruption | Lets scripts and workflow managers react without parsing messages. **Gap:** no peer-reviewed source; this follows the POSIX shell convention for signals. |
| An interruption removes temporary files, and the process ends by the same signal; a signal that was ignored at start-up (`nohup`) stays ignored | [@list2017, Rule 6]. **Gap:** the grace period (3 s) and the PID 1 behaviour follow the documentation of container runtimes and batch schedulers, not peer-reviewed work. |
| The default thread count respects the CPUs a batch scheduler granted on the node | Oversubscribing a shared node slows every job on it. k-mer counting parallelises well across threads [@marcais2011; @manekar2018]. **Gap:** how to read the grant comes from the Slurm, PBS, SGE and LSF documentation. |
| When the system refuses some worker threads (a limit on processes and threads, a lack of memory), the run continues with those it started, warns and records both numbers in the run report; it stops (exit 3) only when the reader, the checksum thread, the interrupt handler or a single worker cannot start. Those essential threads start before the workers | Results do not depend on the number of threads, so a run with fewer gives the same results [@taschuk2017, Rule 10]; a problem is reported, never passed over silently [@seemann2013, Recommendation 5], and the run's log says what happened [@list2017, Rule 7]. **Gap:** no peer-reviewed source compares stopping with continuing; GNU sort also continues with fewer threads, while samtools and xz stop. |

## Outputs and provenance

| Choice | Rationale and sources |
|---|---|
| Results JSON with a versioned JSON Schema, keys of DiMA v5.0.9, and the full provenance of the run (parameters with their origin, input checksum, alphabet decision, validation, diagnostics, references) | Results should be traceable to how they were produced [@sandve2013, Rule 1]; FAIR provenance [@wilkinson2016] [general]; the provenance model of QIIME 2 and Galaxy [@bolyen2019; @goecks2010]. JSON [@rfc8259] [standard]. |
| No timestamps, host names or paths in the results; identical inputs give identical bytes | Software should produce identical results for identical inputs [@taschuk2017, Rule 10]; randomness, if any, must be recorded [@sandve2013, Rule 6] — DiMA has none. |
| Execution facts (times, threads, memory, platform) go to a separate, opt-in run report without user or host names | Keeps results byte-identical while recording how a run went [@gruning2018repro]; field names map onto workflow-provenance vocabularies [@khan2019; @leo2024]. |
| Tidy tables: one observation per row, one variable per column, `NA` for undefined or not computed values, RFC 4180 quoting | [@wickham2014] [general]; [@broman2018] [general]; [@rfc4180] [standard]. |
| Undefined values are `null`/`NA`, never 0 | See [positions without support](/explanation/entropy/#positions-without-support). |
| Similarity-weighted entropy is computed only with `--similarity-weighted-entropy`; its three keys, its summary and its columns are always written, `null`/`NA` when not computed, and the run's parameters record the choice | It is not part of the DiMA method and its evidence base is small (see [the methodology](/explanation/entropy/#similarity-weighted-entropy-opt-in)), so a default run stays exactly the paper's and costs nothing more. Keys that are always present keep one schema and one table layout for every run, so readers never have to test whether a key exists. |
| The keys are named in words, `similarity_weighted_entropy`, `normalised_observed_entropy` and `normalised_similarity_weighted_entropy`, and the summary `similarity_weighted_entropy_summary`; the positions table appends its three columns at the end | Names in words read the same in JSON, the table and the documentation; the paper's symbols ($H_\text{sim}$, $H_n$, $H_\text{nsim}$) would need a legend. Columns added at the end keep the positions of dima 1.0.0's columns for scripts that read them by number. |
| Only the plug-in values are reported, with the statement that they are not corrected for sample size, in the help, the desktop app and the methodology | No published or validated correction exists for similarity-weighted entropy (see [the methodology](/explanation/entropy/#how-the-values-change-with-the-number-of-sequences)); computing one of DiMA's own would change the published method. |
| Results written by dima 1.0.0 are read as runs without the option: the new keys become `null`/`NA` and the parameter `false`. `dima view` says so in a note only when it writes values per position (results JSON or JSONL, or the positions table) | Old results stay usable without conversion. The note explains the empty values where they appear; on outputs without them it would only be noise. |
| `--similarity-weighted-entropy` with no output that holds its values (for example only the variants table) warns `flag_has_no_effect` and the run computes nothing for it; the run's command keeps the flag as typed | The user learns before the run that the option does nothing here, as for the other options that depend on an output, and the run does no work whose result would be thrown away. |
| Outputs are compressed by file extension (`.gz`, `.zst`) | Compressors of sequence data trade size against speed [@kryukov2020]. |
| Outputs are replaced atomically (temporary file, sync, rename); an interrupted run never leaves a partial file | **Gap:** file-system practice, no peer-reviewed source. |
| `dima cite` prints the paper and the exact software version; `dima cite --from` adds the references of the methods a run used; `CITATION.cff` describes the release | Software is often mentioned informally instead of cited [@howison2016] [general]; citations should be specific to the version [@smith2016] [general]; [@katz2021] [general]; tell users how to cite [@lee2018, Rule 10]; FAIR research software [@barker2022] [general]. |

## Engine and performance

| Choice | Rationale and sources |
|---|---|
| One streaming pass; memory grows with the number of distinct k-mers, not with sequences × length | Tools must be ready for data growth [@list2017, Rule 3]. |
| k-mers are interned exactly per position with a rolling hash, every match verified byte by byte | O(1) hash updates per position [@karp1987] [general]; verification rules out collisions. |
| Positions are partitioned among threads, each owning its hash tables | Avoiding locks lets k-mer counting scale with threads [@marcais2011]; the trade-offs of shared and partitioned hash tables on multi-core CPUs [@blanas2011; @balkesen2013] [general]. |
| Exact arithmetic where the paper's method allows it (integer thresholds, exact expectations), compensated summation, platform-independent logarithms | [@taschuk2017, Rule 10]. |
| Every reported entropy is checked to be a finite number of at least 0 bits; a value that is not stops the run as an internal error (exit 1, "please report"), never replaced by another value | Assertions halt a program as soon as something goes wrong [@wilson2014, Practice 5a]; postconditions check that output has the value range required downstream [@hunterzinck2021, Rule 5]; a failure must give a correct exit code [@seemann2013, Recommendation 5]; faults that change output without a crash are the hard ones in scientific software [@kanewala2014] [general]. The estimators guarantee the range (the paper's negative-intercept rule can never apply to the exact expectation), so a violation is a bug. Established tools stop on states their own maths rules out (HMMER/Easel, MAFFT, IQ-TREE, RAxML-NG, Nextclade; tool behaviour); the check costs under 1/100,000 of the run time (measured). |
| Floating-point rounding is measured and documented rather than corrected to the last digit: entropies carry up to $6 \times 10^{-11}$ relative error at 17.5 million sequences per position, $10^{10}$ times below the sampling error (similarity-weighted entropy, which is smaller with the same absolute error, up to $9.7 \times 10^{-10}$, $10^9$ times below it); a prototyped fix is deferred (see [Numerical accuracy](/explanation/numerical-accuracy/)) | Developers of scientific software should analyse round-off error, and two runs that differ only in round-off can give results that significance tests cannot tell apart [@darriba2018, Advanced Best Practices]; accumulated round-off must be shown to be tolerable [@eddy2011]. The mechanism is the loss of the low-order digits of a number close to 1 before its logarithm is taken [@goldberg1991, §1.4 and Theorem 4] [general]. The sampling error comes from the asymptotic variance of the entropy estimate [@paninski2003, Theorem 2] [general]. The fix changes stored digits, so it is not a pure engineering change (working agreement 1). Tools such as scikit-bio, bcftools and SciPy fix precision in ordinary releases, and HMMER points users to archived versions for exact reproducibility (tool behaviour, no peer-reviewed source). |
| Chao–Wang–Jost's second term is evaluated exactly in a time independent of the number of sequences: a series of non-negative terms when it converges fast, otherwise a continued fraction with positive coefficients evaluated backwards, each stopped when the remaining error is below half a unit in the last place, with a 2048-step cap that stops the run as an internal error (see [Numerical accuracy](/explanation/numerical-accuracy/#chaowangjosts-second-term)) | Summed as written the term costs time proportional to $N$ (about 10% of a run) and loses up to 8 digits; evaluated directly it cancels completely (measured). The identities: the hypergeometric series, Pfaff's transformation and the expansion about $z = 1$ [@hankin2015, eqs. 15.1.1, 15.3.4 and 15.3.10] [general]; Gauss's continued fraction and its convergence [@vanvleck1901, p. 1 and §9(a)] [general]; the value between consecutive approximants [@henrici1966, §2] [general]; stable backward evaluation [@jones1974, Theorem 5.1(i)] [general]; the digamma remainder [@alzer1997, Theorem 8] [general]. No domain source evaluates this term other than by summing it (**gap**); domain implementations sum it in $O(N)$ (tool behaviour). |
| Similarity-weighted entropy is computed from residue counts per site, in time proportional to the number of distinct k-mers times k, not from every pair of k-mers; the weights' numerators are exact integers (see [Numerical accuracy](/explanation/numerical-accuracy/#similarity-weighted-entropy)) | Pairs grow with the square of the number of distinct k-mers (201,504,198 pairs on HIV-1 pol DNA, measured). The column-profile form of sum-of-pairs scores gives the same sums [@gotoh1994, eqs. (1) and (4a)], less the matches of each k-mer with its own copies, which Wu's sum over the other k-mers leaves out; the sites are counted in blocks of 2,048, so the table stays in the processor's cache for long k-mers (at $k = 100{,}000$ the option's time fell by three quarters, measured); with every weight 1 the result equals observed entropy bit for bit, because integer conversion and division are correctly rounded [@goldberg1991, §2.1.4] [general]. |
| Normalised values above 1 by no more than rounding (at most $10^{-12}$) are written as 1; a value outside $[0, 1 + 10^{-12}]$, or a similarity-weighted entropy above the observed entropy by more than rounding, stops the run as an internal error | Mathematically both normalised values lie between 0 and 1 and $H_\text{sim} \le \hat H$; a division can exceed 1 by a last-place rounding, which must not be reported as more than the maximum. Anything larger is a bug, handled like the other impossible values. |
| Static Linux builds use the mimalloc allocator | [@leijen2019] [general]. **Gap:** the slowness of musl's allocator under many threads is documented in measurements, not peer-reviewed work; the release workflow measures it. |
| xz input is refused with a hint to decompress it or recompress it with Zstandard, which is recommended for large inputs | Compressors differ widely in decompression speed on FASTA data [@kryukov2020]. An xz file can be decompressed in parallel only when it was written in blocks, which most xz alignments are not, and a damaged file must be refused whatever the number of threads [@taschuk2017, Rule 10]; reading xz on one thread would add a decoder for a format that the large public viral datasets have left for Zstandard. **Gap:** the formats of public datasets and the decompression speeds were checked for this project, not taken from peer-reviewed work. |

## Installation and distribution

| Choice | Rationale and sources |
|---|---|
| Linux binaries built against an old C library (glibc 2.17 for x86_64, 2.28 for ARM64) plus static builds | Many omics tools fail to install, which limits their use [@mangul2019install]. **Gap:** that many HPC clusters still run old Linux distributions comes from community surveys, not peer-reviewed work. |
| Bioconda, BioContainers and Apptainer as the preferred channels once the recipe is accepted | [@gruning2018bioconda; @daveigaleprevost2017; @kurtzer2017; @gruning2018repro]. |
| Release archives with checksums, build-provenance attestations and software bills of materials; CI actions pinned by commit | Defences against supply-chain attacks [@ladisa2023] [general]; pinning alone is not enough [@he2025] [general]; [@zahan2023] [general]. |
| Windows programs link the C runtime statically, and the release checks every Windows program's imports | So that they need no other software installed: without it they need the Microsoft Visual C++ Redistributable, which Windows does not include. **Gap:** an engineering choice; no peer-reviewed source. |
| Unsigned desktop packages with documented first-run steps | **Gap:** code signing needs certificates the project does not hold; no peer-reviewed source. |

## Desktop app

| Choice | Rationale and sources |
|---|---|
| On opening a file, only its first records are inspected (well under a second) and the analysis can start at once; the run is the only full validation | A smooth user experience is key to a tool's adoption [@durant2022, Rule 7]; users should be told about mistakes clearly [@list2017, Rule 6; @lee2018, Rule 9]. Response-time limits of about 0.1 s, 1 s and 10 s [@miller1968] [general]; [@card1991] [general]; errors shown mid-input tend to be ignored [@bargasavila2007] [general]. **Gap:** no domain source states response-time limits. |
| A header editor offering the paper's field names, with a live preview of values and a "copy as `--header-format`" action | Recognition rather than recall, visibility of system status [@nielsen1990] [general]; [@nielsen1994] [general]. |
| Last-used settings are remembered, non-default values are marked, one action resets to the defaults, and the run's provenance records everything | Hidden state undermines reproducibility [@pimentel2019] [general]. |
| The closed Advanced section's title counts the options inside it that differ from their defaults ("Advanced (2 changed)"); one function gives each row's default, for its dot and for the count | A changed option in a closed section is otherwise out of sight, and its results could be taken for those of a default run. Taking the dots and the count from one place keeps them from disagreeing. |
| Similarity-weighted entropy is an Advanced checkbox, off by default and remembered like the other options; when it is off, the app computes and shows nothing of it, and Run details says "not computed" | It is not part of the DiMA method and its evidence base is small, so a default run stays exactly the paper's. Switches, columns and facts for values that were never computed would only be empty noise. Run details states the choice either way, so nobody has to infer it from what is missing. |
| A setting added after 1.0.0 is saved only when it differs from its default | dima 1.0.0 refuses a settings file with keys it does not know and starts from its defaults. Leaving the new key out keeps the settings of everyone who never ticks the option readable by 1.0.0. |
| The entropy chart draws corrected values as a solid line, uncorrected (support ≤ T) values dashed, and positions without support as hatched bands, never as 0 | Colour-blind-safe palette [@wong2011; @hattab2020]; uncertainty encodings [@weiskopf2022]; missing data are not zeros in genome browsers [@kerpedjiev2018; @kent2010]; position along a common scale is read most accurately [@cleveland1984] [general]; labelled gaps are the best-understood treatment of missing data [@eaton2005] [general]; breaking a line lowers perceived quality, so it is kept for absent data [@song2019] [general]; dashing and lightness read as uncertainty [@maceachren2012] [general]; colour is never the only cue and graphics reach 3:1 contrast [@wcag22, SC 1.4.1 and 1.4.11] [standard]. |
| The hatched "no usable support" band is drawn only where support is 0, for either metric; a position with support but no value breaks the line | The band states a fact about support, which would be false at a supported position (an edited results file can hold `null` there); a break shows that a value is missing without saying why. |
| Long ranges are drawn with M4 downsampling, which keeps every peak and trough | [@jugel2014] [general]. |
| When the run computed similarity-weighted entropy, a "Metric:" switch of two radio buttons on its own row above the chart plots either metric. A switch keeps the zoom and the selection (the table scrolls back to its row when positions hidden by a narrowed range come back) and resets only the value range of the filters, with a note when the user had narrowed it. The heading, the legend captions and the filter label that change with the metric keep the width of the longer of their two texts, the filter's two value fields show four decimals at the width of the wider of the two metrics' largest values, and the count and Reset start a row of their own whenever the longest count would not fit at the end of the bar, so no button, filter or the chart moves. A drag moves a bound of the value range by 1/200 of the metric's full range per pixel, but by at least 0.0001; a minimum that reads as 0 is 0, and a maximum that reads as the largest value is that value exactly | Comparing the two metrics over the same positions is the point of the switch, so the view the user chose stays. A value range chosen for one metric means nothing for the other, so it starts over at the full range, and the note says why the chart may show more positions. Radio buttons show both choices and which one is on; because nothing moves, switching back and forth is one click in the same place. A value field otherwise picks its number of decimals from its drag speed, which follows the metric's largest value, and from the screen's pixel size, so its width would change with the metric; a count that the switch shortens or lengthens ("7 of 1345 positions", "1345 of 1345 positions") would move Reset to another row at some widths. A step that follows the range crosses either metric's range in the same 200 pixels, whatever its scale; a fixed 0.01 bits per pixel crossed the bundled MERS spike sample's entropy range (1.59 bits) in 159 pixels but its similarity-weighted range (0.45 bits) in 45. 0.0001 is the last decimal the fields show. A field stores the text it showed when it loses the focus, so tabbing through the largest value on the way to the switch would otherwise narrow the range by the rounding, hide the positions at that value and make the switch report a narrowed range. |
| Every dataset opens showing entropy | Entropy is the method's measure and the one its summaries report; a dataset opened later should not inherit a view chosen for another one. |
| Each metric has its own value axis (0 to 5% above the largest value shown, at least 0.005 bits), axis title, ticks and mean line | Similarity-weighted entropy is often a small part of the entropy (on the bundled MERS spike sample its eligible mean is 0.0363 bits, against 0.1207 bits of observed entropy at the same positions); on a shared axis its line would be nearly flat. |
| The metric is named in full words everywhere: "Similarity-weighted entropy" in the switch, the chart's heading, axis title ("Similarity-weighted entropy (bits)"), the figure's title, the filter label, the note, the position facts and the tooltip, "Similarity-weighted" as the table's header and "similarity-weighted mean" on the chip; no symbol such as H_sim | A symbol means nothing to someone who has not read the methods, and the same words in every place let the metric be recognised wherever it appears. The table header is shortened to keep the column narrow; its tooltip, "Sort by similarity-weighted entropy", gives the full name. |
| The similarity-weighted chip comes right after the mean chip and gives the mean observed entropy of the same eligible positions in parentheses | The mean chip is the run's entropy, which the paper's estimator corrects; the similarity-weighted value is a plug-in value, so the like-for-like comparison is with the observed mean of the same positions. |
| The position table's similarity-weighted column comes right after Entropy; in exported tables it stays at the end | On screen the two entropies are read side by side. Files keep the column order of dima 1.0.0 and of the command line, so scripts that read columns by position keep working. |
| The position table scrolls sideways when its columns do not fit, keeping every column's minimum width; a header reached with Tab scrolls into view, and moving through the rows with the arrow keys keeps the sideways position | Squeezing columns below their minimum would cut their values; scrolling keeps them whole. A table that jumped back to its left edge at every arrow key could not be read on its right-hand columns. |
| The three similarity facts sit in a second grid below the others, and both grids share one key column; a value too long for its column wraps, before the panel's scroll bar | The facts every run has stay where they always were, and one key column lines all values up, so they can be compared down the column. A long value, such as a method with its fallback, used to be cut at the panel's edge, and then ran under the scroll bar, which floats over that edge while the pointer is over the panel. |
| At support ≤ T the two normalised values are marked "(low support)" in words, in the facts and the chart's tooltip; nothing else is marked | Normalised values from a few sequences mislead most easily: where every sequence carries a different k-mer, normalised observed entropy is 1 by arithmetic alone (16 of the 41 marked positions of the bundled HIV-1 pol protein data set). A word is read by everyone, including people who cannot tell colours apart and screen-reader users, and marking only these two values keeps the mark meaningful. |
| Axis labels never repeat or overlap: positions are labelled in whole-number steps of at least 1, and the entropy axis keeps two decimals but uses three when its ticks are less than 0.01 bits apart; that axis is at least 0.005 bits tall (1 bit when every shown value is 0). The chart and the exported figures label their axes alike | A repeated label, such as 0.00, 0.01, 0.01 for ticks 0.005 bits apart, misstates the scale. On an axis at least 0.005 bits tall the ticks are at least 0.001 bits apart, so three decimals always tell them apart and every label fits the axis margin in at most five characters. |
| Values are shown with a fixed number of decimals, but a value that is not zero never reads as zero (`< 0.0001`, `< 0.1%`), and a coverage, incidence or conservation bound below its maximum never reads as the maximum (`> 0.9999`, `> 99.9%`). Sorting and exports keep every digit; the command line's end-of-run line follows the same rule | A rounded zero would say that a position does not vary, and a rounded maximum that every sequence agrees, when neither is true. |
| Exported figures are at least 720 × 320 px. Their legend continues on further rows when it is wider than the plot, and a title, subtitle or legend label that does not fit is shortened with "…" (the SVG keeps the whole title as its document title). Text is sized per em in the PNG as in the SVG and on screen, and the title is SemiBold in both formats | Below that size the title, a legend of three rows and the axes no longer fit around a plot at least 100 px tall. A figure should look the same whichever format is chosen. A saved size below the minimum is raised once, with a note, rather than resetting every other setting. |
| In a small window the column with the chart, the conserved regions and the position table scrolls, and the table keeps at least four rows; the mouse wheel over the chart zooms it and never scrolls the column. The fact chips, the filter bar and the chart's heading row wrap between whole items, and the chart's Fit, + and − buttons stay at the top right of the chart, after its heading and legend for screen readers | The smallest window (980 × 620 px) cannot hold the chart, the conserved regions and a usable table at once; scrolling keeps every part reachable without shrinking the chart below a readable height. Zooming is the chart's main gesture, so the wheel belongs to it. A chip split over several lines, or a label drawn over a control, is hard to read and can hide the control. The buttons are laid out first, so the heading row wraps beside them, but a screen reader meets them where the row ends, as a sighted reader does. |
| The metric switch is reached with the keyboard by egui's own keys: Tab and Shift+Tab move between controls, Space selects, and while a button, check box or radio button has the focus the arrow keys move between controls and never along the table (in a value field Up and Down change the value and Left and Right move the text cursor; in a text field the arrow keys move the text cursor); Esc gives them back. The command palette offers the metric not shown; there is no shortcut of its own. The keyboard help lists these keys | The standard keys need no learning, and an arrow key never does two things at once. Esc is the key that already closes the palette, so it is listed where users look for it. A shortcut of its own would be one more key to remember for an occasional action; the palette finds the switch by name. |
| A click anywhere in a table row selects it, its text included; copying goes through a row's right-click menu (**Copy row**, and **Copy k-mer** for variants), and the cells' text cannot be selected | Selectable text took the click, so a click on a cell's text did nothing while a click beside it selected the row (in 1.0.0 too), and the table had no other way to copy. Data tables in spreadsheets, file browsers and sequence viewers select a row with a click anywhere and copy through a menu; a row copied as tab-separated cells pastes into a spreadsheet as one row. |
| No table cell is a keyboard stop: the position table's rows move with the arrow keys, and each variant the variant table shows whole is one stop, its sequence, where Space or Enter selects it. A column header or variant that has the focus is outlined | With a stop on every cell, Tab crossed 16 cells that showed nothing before it reached the metric switch on the bundled MERS spike sample, and 52 on the HIV-1 pol protein data set, and a keyboard user cannot tell where an invisible focus is. The rows of positions already move with the arrow keys; one stop per variant keeps choosing a variant for its metadata possible without a mouse, and only rows shown whole get one, so the outline is always in view. A frameless header and a label draw no focus of their own. |
| A value typed into a filter field is applied when it is entered (Enter, Tab or a click elsewhere), and Esc leaves the field unchanged; a typed bound is kept to the four decimals the field shows. Each field is named by what it bounds (*First position shown*, *Highest entropy shown, in bits*), as its tooltip and for screen readers, and nothing after a field moves while it is typed in | Applied at every key, the first digit of 0.2 typed as the maximum set the range to 0 to 0, hid the selected position and moved the selection away for good, and the chart and table redrew at every digit. egui reads back the text a field shows when it loses the focus, so a bound kept with more decimals than shown (0.111293, shown as 0.1113) changed when the field was next passed through, hid a position and reset the zoom with no visible edit. A field that shows only "max 1.5878" does not say what it bounds; the name says it once, as the name rather than again as a description. A field that narrowed while it was typed in, or when its number got shorter, moved every control after it. |
| Notifications stack upwards from 16 px above the window's bottom-right corner, the newest nearest the corner, each as wide as its message and buttons (at most 380 px); a message wraps beside its buttons, which sit at its top right, and screen readers read the message before them | Laid out from the bottom, a message that wrapped grew downwards past the window's edge, its close button half off it. The top right is where a close button is looked for, and reading the message first says what is being dismissed. A warning stays until it is dismissed, so it covers no more of the window than its text needs. |
| An option's change dot has its place even when no dot is shown | The dot widened the column of option names when it appeared on the widest one, so every control of the grid moved under the pointer and a second click at the same place missed. |
| Results of a newer schema open with the warning `dima view` gives (`newer_schema`) | The app keeps only the fields this version knows, so an export from it would leave out the others without a word; the app and the command line say the same thing about the same file. |
| Close buttons show × (U+00D7), and egui's monospaced Hack ends the fallback chain of the interface's proportional faces | ✕ (U+2715) is in none of the bundled faces or egui's, so it showed as an empty box, as did ▸ in the Cite window and the ▼ that marks a low coverage in the position table, which only Hack draws. Being last, Hack draws only what no other face has, so no other text changes. |
| Exported figures are named by their metric (`<query>.similarity-weighted-entropy.png`), and the export menu and its tooltips say which chart they save | Both figures of a dataset can be kept side by side without renaming them, and the name says which is which. |
| A figure is saved only for the metric the chart showed when its export was chosen: if the chart was switched while the save dialog was open, nothing is saved and a warning says so and what to do | The file would otherwise hold one metric's figure under the name chosen for the other. Saving nothing, with the reason and the fix, is how the app already handles results replaced while a save dialog is open. |
| Native file dialogs with an automatic fallback to a built-in browser, and a path field | A tool should be OS agnostic [@durant2022, Rule 8]. **Gap:** the fallback heuristics follow other desktop toolkits, not peer-reviewed work. |

## Documentation

| Choice | Rationale and sources |
|---|---|
| Tutorials, how-to guides, reference and explanation as separate kinds of pages; quick start first | A quick start that tells users exactly how to get a result in a few explicit steps on a specified test data set, at the beginning of the documentation [@karimzadeh2018, Quick start and Key Points; @lee2018, Rule 3]; components grouped hierarchically, the most important at the top [@karimzadeh2018, Hierarchical documentation]; a reference manual with every configurable setting, input and output [@karimzadeh2018, Table 1]. The four kinds of page are DiMA's choice. |
| A short FAQ whose questions are phrased as users ask them and whose answers link to the full page; a Glossary of the terms in the results; Troubleshooting for every message | Karimzadeh & Hoffman recommend an FAQ, which "is easier to link to an answer" than a manual, and a separate chapter that explains error and warning messages; 14 of the 22 selected, well-established packages they describe have an FAQ [@karimzadeh2018, Table 2]. A missing FAQ and readers unsure where to start are among the documentation issues found in practice [@aghajani2019] [general]. |
| Numbers of the documentation that come from expectations or simulations, not from a dima run, are written by `scripts/reference/docs_numbers.py` between markers in the pages, and CI fails when a page and the script disagree. The script computes exactly wherever an exact form exists and uses seeded Monte Carlo, with its run counts and 95% half-widths in the text, only where none exists | Numbers copied by hand go stale when the method or the data change; generated and checked, they cannot. Exact values need no tolerance and are the same on every machine; seeded simulations are reproducible and say how precise they are. |
| Questions go to GitHub Discussions, bugs to GitHub Issues through a form that asks for the version, the command and the run report | Expect support requests and give users a channel for them [@list2017, Rule 10]; 16 of those 22 packages offer a forum or mailing list [@karimzadeh2018, Table 2]. |
| One published version of the documentation per release, plus the development version (the `master` branch) | Version-control the documentation [@lee2018, Rule 6]; archival stability [@mangul2019install]. |
| Search engines index only the current documentation (`/latest/`): the pages of each release carry `noindex` and their own canonical address. `dima --help`, the desktop app and `CITATION.cff` link the documentation of their own version, and `/latest/` says when it describes changes not yet released | Readers should find documentation that matches the version they run [@lee2018, Rule 6]. Outdated documentation is a common problem: among up-to-dateness issues, outdated references such as links to old versions were the most prevalent [@aghajani2019] [general], and most obsolete answers on a question-and-answer site are never updated [@zhang2021] [general]. A canonical address must point to the same content or a superset of it, so a release page cannot name `/latest/` [@rfc6596, Section 3] [standard]; a site under a project path cannot serve the `/robots.txt` file that crawlers read from the root of the host [@rfc9309, Section 2.3] [standard], so each page carries the tag. |
| Every scientific statement cites its sources, from the same registry as the program's help | One registry gives the help, the desktop app and the documentation the same references, so a source cited in one place is never missing or different in another. |
| Citations show author and year, link to the page's reference list (which links back) and preview the full reference on hover or keyboard focus; the reference texts are those of `dima cite` | On desktop computers readers mostly hover over a citation to see its reference; on phones they tap it [@piccardi2020] [general]. Links from citations to the reference list and back let blind and low-vision readers resolve a citation without losing their place [@wang2021] [general]. The same work has different reference numbers in different documents, which makes citations harder to keep track of [@lo2024] [general]. Roles for citations, reference lists and back-links [@dpubaria11] [standard]; previews can be dismissed with Escape, hovered and stay until the pointer or focus leaves [@wcag22, SC 1.4.13] [standard]. **Gap:** no peer-reviewed study compares author-year with numbered citations for readability. |
| Labels are computed once over the whole registry, so a work has the same label in the help, the desktop app and every page: works that would share a label show more names (`Grüning, Dale et al. 2018`, `Grüning, Chilton et al. 2018`), then year letters for identical authors, which appear only in DiMA's own reference lists, never in exported references | A label must lead to exactly one entry of the reference list; labels computed page by page would give the same work different labels on different pages. **Gap:** the order (names first, then letters) follows the author-date style manuals and the Citation Style Language 1.0.2 specification, not peer-reviewed work. |
| Standards are labelled by the designation their publisher gives them (`RFC 8259`, `UAX #15`, `WCAG 2.2`), without a year, and DiMA's reference lists start their entries with it; each cites the dated version that DiMA follows | RFCs are cited by their numbers [@rfc7322, Section 3.5] [standard], and the W3C and the Unicode Consortium document the same short forms. Designations are unique and searchable, and need no year letters. **Gap:** articles in bioinformatics journals mostly cite standards by their editors' names; no study compares how readers recognise either form. |
| WCAG 2.2 AA, checked on every page by automated scans in both themes; formulas carry MathML for screen readers | [@wcag22] [standard]. |
| No analytics, trackers or advertising | Readers' privacy. **Gap:** a principle, not a cited finding. |
