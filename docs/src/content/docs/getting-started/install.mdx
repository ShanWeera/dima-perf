DiMA comes as a **command-line tool**, `dima`, for analyses, scripts and clusters, and as a
**desktop app**, `dima-gui`, for interactive exploration. Both are single programs that need no
other software installed (on Linux the desktop app uses the system's graphics: X11 or Wayland,
and Vulkan or OpenGL, present on any desktop), published for 64-bit Linux, macOS and Windows on
x86_64 and ARM64 (the desktop app for Windows on x86_64 only) on the
[releases page](https://github.com/ShanWeera/dima-perf/releases). The commands below use version
1.0.0; replace it with the release you want.

## Command line

<Tabs syncKey="os">
<TabItem label="Linux">

Choose the build for your system:

| System | Archive (`dima-1.0.0-….tar.gz`) |
|---|---|
| x86_64 with glibc 2.17 or newer: CentOS/RHEL 7 and later, Rocky and Alma Linux, Ubuntu, Debian, most HPC clusters | `x86_64-unknown-linux-gnu` |
| ARM64 with glibc 2.28 or newer: RHEL/Rocky 8 and later, Ubuntu 18.10 and later, Debian 10 and later | `aarch64-unknown-linux-gnu` |
| Any Linux, statically linked: Alpine, minimal containers, very old systems | `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl` |

`ldd --version` prints your glibc version. Prefer the `gnu` builds where they run; the `musl`
builds are fully static and use the mimalloc allocator to stay fast with many threads.

```sh
VERSION=1.0.0
TARGET=x86_64-unknown-linux-gnu
BASE=https://github.com/ShanWeera/dima-perf/releases/download/v$VERSION
curl -fLO "$BASE/dima-$VERSION-$TARGET.tar.gz"
curl -fLO "$BASE/SHA256SUMS"
grep " dima-$VERSION-$TARGET.tar.gz\$" SHA256SUMS | sha256sum --check
tar -xzf "dima-$VERSION-$TARGET.tar.gz"
mkdir -p ~/.local/bin
cp "dima-$VERSION-$TARGET/dima" ~/.local/bin/
dima --version
```

No root access is needed. If `dima` is not found, add `~/.local/bin` to your `PATH`.

</TabItem>
<TabItem label="macOS">

One archive per processor: `aarch64-apple-darwin` for Apple silicon (M1 and later),
`x86_64-apple-darwin` for Intel Macs (`uname -m` prints `arm64` or `x86_64`).

```sh
VERSION=1.0.0
TARGET=aarch64-apple-darwin
BASE=https://github.com/ShanWeera/dima-perf/releases/download/v$VERSION
curl -fLO "$BASE/dima-$VERSION-$TARGET.tar.gz"
curl -fLO "$BASE/SHA256SUMS"
grep " dima-$VERSION-$TARGET.tar.gz\$" SHA256SUMS | shasum -a 256 --check
tar -xzf "dima-$VERSION-$TARGET.tar.gz"
mkdir -p ~/.local/bin
cp "dima-$VERSION-$TARGET/dima" ~/.local/bin/
dima --version
```

Files downloaded with `curl` can run directly. If you downloaded the archive with a web browser,
macOS marks the program as downloaded and refuses to run it because it is not signed; remove the
mark with `xattr -d com.apple.quarantine ~/.local/bin/dima`.

</TabItem>
<TabItem label="Windows">

One archive per processor: `x86_64-pc-windows-msvc` for most PCs, `aarch64-pc-windows-msvc` for
ARM64 devices. In PowerShell:

```powershell
$Version = "1.0.0"
$Target = "x86_64-pc-windows-msvc"
$Base = "https://github.com/ShanWeera/dima-perf/releases/download/v$Version"
Invoke-WebRequest "$Base/dima-$Version-$Target.zip" -OutFile "dima-$Version-$Target.zip"
Invoke-WebRequest "$Base/SHA256SUMS" -OutFile SHA256SUMS
(Get-FileHash "dima-$Version-$Target.zip" -Algorithm SHA256).Hash.ToLower()
Select-String "dima-$Version-$Target.zip" SHA256SUMS     # the two hashes must match
$Dir = "$env:LOCALAPPDATA\Programs\dima"
Expand-Archive "dima-$Version-$Target.zip" -DestinationPath $Dir -Force
$UserPath = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$UserPath;$Dir\dima-$Version-$Target", "User")
```

Open a new terminal, then run `dima --version`.

</TabItem>
</Tabs>

Each archive also contains shell completions (`completions/`), the README, the licence and
third-party notices, the changelog and `CITATION.cff`; the Linux and macOS archives also contain
manual pages (`man/man1/`). Completions can also
be generated by `dima completions bash|zsh|fish|powershell|elvish`; for example, for bash:

```sh
mkdir -p ~/.local/share/bash-completion/completions
dima completions bash > ~/.local/share/bash-completion/completions/dima
```

### Verify the download

Every release lists the SHA-256 checksum of each file in `SHA256SUMS` (checked above), and
carries a signed build-provenance attestation that ties each file to the release workflow that
built it from the tagged source. With the GitHub CLI:

```sh
gh attestation verify dima-1.0.0-x86_64-unknown-linux-gnu.tar.gz --repo ShanWeera/dima-perf
```

### Build from source

With Rust 1.85 or newer ([rustup](https://rustup.rs/)):

```sh
cargo install --locked --git https://github.com/ShanWeera/dima-perf --tag v1.0.0 dima
```

`--locked` builds with exactly the dependency versions of the release. On Windows, `cargo install`
does not apply the repository's build settings, so the program it builds needs the Microsoft
Visual C++ Redistributable; for a self-contained program like the release archives, run
`$env:RUSTFLAGS = "-C target-feature=+crt-static"` in PowerShell first.

### Bioconda and containers

A Bioconda recipe is ready and will be submitted; once it is accepted, `conda install -c bioconda
dima` and the matching BioContainers Docker and Apptainer/Singularity images will become the
easiest way to install DiMA on clusters [@gruning2018bioconda; @daveigaleprevost2017;
@kurtzer2017]. Until then, use the archives above, which run on any Linux, in containers too.

## Desktop app

The desktop app needs macOS 11 or newer, Windows 10 or newer on x86_64, or Linux with glibc 2.28
or newer and a graphical session (X11 or Wayland).

<Tabs syncKey="os">
<TabItem label="Linux">

| Package | For |
|---|---|
| `DiMA-1.0.0-x86_64.AppImage`, `…-aarch64.AppImage` | any distribution: make it executable and run it |
| `dima-gui_1.0.0_x86_64.deb`, `…_aarch64.deb` | Debian, Ubuntu and derivatives |
| `dima-gui-1.0.0-x86_64-linux.tar.gz`, `…-aarch64-linux.tar.gz` | systems without FUSE, such as many HPC login nodes |

```sh
chmod +x DiMA-1.0.0-x86_64.AppImage
./DiMA-1.0.0-x86_64.AppImage
```

The AppImage needs FUSE 2 (`libfuse2`, called `libfuse2t64` on Ubuntu 24.04); without it, run
it with `--appimage-extract-and-run`, or use the `.tar.gz`. Install the `.deb` with
`sudo apt install ./dima-gui_1.0.0_x86_64.deb`.

</TabItem>
<TabItem label="macOS">

`DiMA-1.0.0-universal.dmg` runs on Apple silicon and Intel Macs. Open it and drag DiMA to
Applications.

The app is not yet signed by an Apple developer certificate, so macOS blocks the first launch.
On macOS 15 (Sequoia) and later:

1. Open DiMA. macOS reports that it could not verify the app; choose **Done**.
2. Open **System Settings ▸ Privacy & Security**, scroll to **Security**, and choose
   **Open Anyway** next to the message about DiMA.
3. Confirm with your password or Touch ID, and choose **Open Anyway** once more.

macOS remembers the decision. On earlier versions, Control-click the app, choose **Open**, then
**Open**. Alternatively, in Terminal: `xattr -dr com.apple.quarantine /Applications/DiMA.app`.

</TabItem>
<TabItem label="Windows">

`DiMA-1.0.0-x86_64.msi` installs the app; there is no Windows ARM64 build of the desktop app
yet. The installer is not yet code-signed, so Microsoft Defender SmartScreen may show
"Windows protected your PC": choose **More info**, check that the app is DiMA, then
**Run anyway**.

</TabItem>
</Tabs>

To build the desktop app from source instead, use Rust 1.95 or newer and replace `dima` with
`dima-gui` in the `cargo install` command above; on Linux this needs the X11, Wayland and Vulkan
development packages (see `scripts/ci/install-gui-deps.sh` in the repository).
